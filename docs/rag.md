# Tathya source questions (RAG)

The audit result page includes **Ask your sources**. It calls authenticated `POST /api/v1/audits/{audit_id}/ask` with `{ "question": "What warranty period is specified?", "top_k": 5 }`.

Access follows the existing audit permissions: owners can ask about their audit; reviewer/admin access is unchanged. Retrieval reads only current `kind=source` documents in that audit, never the audited primary or another audit's sources. No new schema or dependencies are needed.

Retrieval reuses the existing BM25, normalized dense embedding, reciprocal-rank fusion and optional cross-encoder runtime. If dense models fail, lexical retrieval remains available. Queries with no relevant candidates abstain. The relevance threshold is a heuristic, not a probability or verification score. Source corpora are rebuilt on demand, so current versions are used without a stale persistent index; large source packs will need indexing/batching later.

Generation uses the existing provider-neutral `LLMAdapter` and configured provider keys/models, retries and disk cache. Each generation request contains at most eight source excerpts of at most 4,000 characters each. Missing providers return `generation_unavailable` and actual excerpts, never a fabricated generated answer. Questions without sufficient evidence return `insufficient_evidence`.

An `answered` result contains server-added citation markers and citations with document ID, filename, version, text hash, sentence ID, exact quote, character offsets and retrieval rank score. Unknown/missing citation IDs and malformed output are rejected. Source versions are rechecked after generation; changed sources invalidate the answer. Statements are generated by a model: citation validity alone does not prove semantic correctness, so users must review the excerpts. Answers do not alter verification findings, trust scores or passports.

Uploaded excerpts are delimited as untrusted data in the prompt. The generator receives no tools or write capabilities. Provider generation sends excerpts to the configured provider and uses the existing local LLM cache; apply the application's normal provider and retention policies.

## Validation

Run `.venv/Scripts/python.exe -m pytest --noconftest backend/tests/test_rag.py -q` from the repository root. These tests create isolated in-memory SQLite tables and stub models/providers. They do not query production databases or require provider credentials. Regression coverage includes audit isolation, stale/primary exclusion, exact quote offsets, citations, abstention, unavailable generation, source updates, authorization and input limits.

## Retrieval hardening

Lexical retrieval supports Unicode words, including complete Hindi words with Devanagari vowel marks, alongside Indian currency and identifiers. Invalid, non-finite or zero-length embedding responses fall back to lexical retrieval. Citations with invalid character ranges are excluded. Before an answer is accepted, source audit membership, source kind and immutable version are rechecked alongside text hashes and exact quotes. These checks do not calculate truth or change trust scores.
