# Contributing to Tathya

Use the [development guide](development.md) to set up the project. Component-specific instructions are in the [backend guide](backend/README.md) and [frontend guide](frontend/README.md).

## Changes

Keep changes focused and preserve existing API contracts, authentication and document workflows. Coordinate changes to shared contracts with the backend and frontend owners. Preserve license and attribution notices.

Do not commit secrets, generated bundles, test reports or local review captures. Use the checked-in manifests and lockfiles for dependencies.

## Validation and pull requests

Run the configured build, lint, type checks and tests relevant to the change. Add or update tests when behavior changes.

Describe the problem, resulting behavior and validation in the pull request. Include any remaining limitations and reference related issues when available.
